# 研究议程：HTML 动画 × PPT 结合技术

> 状态：研究设计
> 日期：2026-11-14
> 关联：[架构](01-architecture.md)、[实验与发现](02-experiments-and-findings.md)、[路线图](03-roadmap.md)

## 1. 研究定位

这不是“如何录一段屏”或“如何做一个插件”的工程问题，而是三个层面的边界研究：

1. **保真层**：HTML 动画的确定性过程如何在不改 PPT 运行时的前提下进入幻灯片。
2. **运行层**：需要完整交互时，PPT 如何与本地浏览器安全、可控地共存和切换。
3. **可靠性层**：现场环境（WPS/Office、Windows 前台锁、杀毒/策略、版本差异）下，如何把失败模式变成可观测、可恢复的工程问题。

## 2. 核心研究问题

| # | 问题 | 假设 | 验证方式 |
|---|------|------|----------|
| RQ1 | 能否把 HTML 动画的“过程”做成 PPT 原生可播放的分步？ | 逐帧捕获 + 分步视频 + 原生单击动画可以保留过程，且不增加页数 | 2 步样例在 WPS/Office 放映态验收；边界帧像素比较 |
| RQ2 | WPS/Office 的播放约束是什么？ | WPS 对单段媒体时长敏感；Office 更宽松；页数/点击序列是主要限制 | 不同时长/段数的对照实验 |
| RQ3 | 需要完整交互时，能否用本地浏览器作为 PPT 的“外部动画运行时”？ | 先退出 WPS 放映，再让 Edge 全屏接管，可以避开全屏覆盖层 | 模式 B 现场实测与日志 |
| RQ4 | 能否让 PPT↔Edge 切换“基本无缝”？ | 渐黑/保持/渐透明 + 就绪信号可以隐藏切换缝；返回侧需要提前信号 | 黑场时序日志、截图、返回侧日志 |
| RQ5 | 如何让自动化在现场稳定？ | 前台锁、COM 瞬时错误、Edge 同步弹窗、进程残留都可以用工程手段收敛 | 故障注入实验；自动清理验证 |
| RQ6 | 如何量化保真度、延迟和失败率？ | 边界像素差、触发到可交互延迟、切换黑屏时长、失败恢复率可作为指标 | 评测 harness + 现场日志 |

## 3. 指标

### 保真度

- 相邻步骤边界帧的像素差（源 PNG，而不是解码 MP4）。
- 步骤数、每步时长、总时长与 HTML 契约的一致性。
- PPTX 页数变化（模式 A 只允许 +1 页；模式 B2 要求 0 页变化）。
- 原页面形状/文本/动画 XML 的 C14N 一致性（模式 B2 不应改动内容）。

### 延迟

- 触发（空格/点击）到 HTML 可交互的时间。
- 黑场渐入/保持/渐出时长。
- 返回时 WPS 恢复并聚焦的时间。
- 首段视频自动播放到可见首帧的时间（模式 A）。

### 可靠性

- 触发成功率、重复触发率、返回失败率。
- WPS COM 瞬时错误率与重试恢复率。
- 进程/锁残留率（watcher、Edge、黑场、agent）。
- 首次运行安全提示次数、Edge 同步弹窗出现率。

### 可复现性

- 从干净环境到可放映产物的步骤数。
- 捕获/编码/组装的可重复性（同输入同输出）。
- 现场机器与开发机器的差异清单。

## 5. 研究产出

- 一套可复用的捕获/编码/组装工具链（模式 A）。
- 一套实时浏览器桥接工具链（模式 B/B2）。
- 一份 WPS/Office/Edge 兼容性矩阵与失效模式库。
- 一套可复现的评测脚本与验收清单。
- 技术报告/论文素材：问题定义、架构、实验、限制。

## 6. 非目标

- 不做 PowerPoint/WPS 的内嵌 WebView2/ActiveX 控件（WPS 不支持，Office 场景需单独验证）。
- 不依赖 VBA 宏或联网插件。
- 不追求“任意 HTML 页面零改造”；HTML 需要遵守分步契约或返回信号契约。
- 不承诺 macOS/Linux 上的模式 B/B2；Windows 是目标环境。

## 7. 方法

1. 先冻结页面与上下文，建立 2 步真实样例。
2. 用对照实验隔离变量（时长、段数、启动顺序、焦点、黑场时机）。
3. 用日志记录每个组件边界的输入/输出与失败码。
4. 先证明边界可控，再扩展业务页面。
5. 每个结论都保留可复现命令、截图或日志片段。
