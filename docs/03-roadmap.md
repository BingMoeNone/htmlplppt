# 研究路线图

> 状态：规划
> 日期：2026-11-14
> 关联：[研究议程](00-research-agenda.md)、[架构](01-architecture.md)、[实验与发现](02-experiments-and-findings.md)

## 1. 当前基线（Phase 0）

已完成并可复现：

- 模式 A：契约检查、CDP 逐帧捕获、H.264 编码、WPS 时长压缩、native/appear 组装、结构校验、WPS 冒烟。
- 模式 B：自动监视器、Edge 全屏应用窗口、前台锁处理、WPS 恢复、应急停止。
- 模式 B2：现有内容页空格触发、黑场过渡、常驻聚焦 agent、返回标题信号、COM 重试与自动清理、Edge 同步参数组。
- 参考文档：HTML 契约、PPTX 时序、兼容性、实时浏览器、空格触发 + 黑场。
- 案例：LyMtrix 20 页 live 稿 + 9 页初赛短版。

## 2. Phase 1：兼容性矩阵与基线

目标：把“某台机器能跑”变成“哪些环境能跑、失败时怎么降级”。

交付：

- WPS 12.1 / 11.x / 13.x + Office 2016/2019/365 的播放矩阵。
- Edge 版本与参数组/策略的兼容矩阵。
- 字体、DPI、多显示器、杀毒/组策略的预检清单。
- 失败模式库：视频点击失效、全屏覆盖、前台锁、COM 错误、同步弹窗、进程残留。

验收：

- 至少 2 个 WPS 版本、1 个 Office 版本、2 台不同 DPI 的机器完成同一套验收脚本。
- 每个失败模式都有日志特征和降级路径。

## 3. Phase 2：模式 A 工程化

目标：让“HTML → 分步视频 → PPTX”成为可重复构建，而不是手工渲染。

交付：

- 捕获器支持断点/局部重渲染，manifest 可审计。
- native/appear 双模式自动回退。
- WPS 压缩参数的版本化配置（≤0.9s 基线，可按版本调整）。
- 边界像素差报告与阈值。
- 组装器的页数/位置/C14N/视频数门禁。
- 2 步样例 + 全量构建的自动化脚本。

验收：

- 同一输入两次构建的边界差、页数、视频数一致。
- 原页 C14N 不变。
- WPS/Office 放映态人工验收通过。

## 4. Phase 3：模式 B/B2 工程化

目标：让实时 HTML 桥接在现场稳定、可恢复、可观测。

交付：

- 统一的“目标页 → HTML”配置格式（当前为 VBS CONFIG，可扩展为 JSON）。
- 常驻 agent 的 arm/ready/exit/return 协议文档化。
- 黑场时序参数化（渐入/保持/渐出/最大保持）。
- 前台聚焦自检与目标机预检。
- COM 错误重试/清理策略的参数化。
- Edge 同步/首启参数组与策略兜底脚本（可选、可撤销）。
- 单实例锁、心跳、应急停止的完整验证。

验收：

- 触发成功率 ≥ 99%（100 次触发）。
- 无重复触发、无残留进程、无同步弹窗。
- 返回侧无 WPS 编辑器露出。
- 故障注入（杀 WPS、杀 Edge、断网、锁屏）后可恢复或安全退出。

## 5. Phase 4：评测与可复现性

目标：把“看起来能用”变成可量化指标。

交付：

- 评测 harness：输入 deck + HTML + 配置，输出保真度/延迟/失败率报告。
- 自动验收：页数、C14N、视频数、边界差、触发时序、进程清理。
- 现场日志规范：watch/bring/cover/agent 四类日志的字段与采样。
- 可复现实验包：环境清单、命令、期望输出、截图。

指标：

- 边界像素差 P95。
- 触发到可交互 P50/P95。
- 黑场时长 P50/P95。
- 失败恢复率、残留率。

## 6. Phase 5：研究产出

- 技术报告：问题定义、架构、实验、限制。
- 兼容性矩阵与失效模式库。
- 参考实现与模板包。
- 论文/专利素材（如需要）：确定性捕获协议、双模式路由、黑场切换协议、可靠性机制。

## 7. 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| WPS 版本变化 | 视频点击/覆盖层/COM 行为变化 | 版本矩阵 + 预检 + 降级 |
| Office 与 WPS 差异 | 同一产物行为不同 | 双环境验收；模式 A native/appear 回退 |
| 安全软件/组策略 | 脚本/焦点/参数被阻止 | 预检 + 日志 + 人工兜底 |
| Edge 同步/首启弹窗 | 现场体验破坏 | 参数组 + profile 重置 + 可选策略 |
| 返回侧黑场过长 | 节奏变慢 | 优化 ResumeShow；参数化页面延迟 |
| 文件分发遗漏 | 模式 B/B2 无法启动 | 同目录清单 + zip + 预检 |
| 生成物入库 | 仓库膨胀 | .gitignore + 构建脚本 |

## 8. 下一步优先级

1. 在 PowerPoint（非 WPS）上复测模式 A/B/B2，补齐兼容性矩阵。
2. 把模式 B2 的 CONFIG 从 VBS 迁移为可校验的 JSON/环境变量（保持 VBS 兼容）。
3. 做触发/返回的 100 次稳定性测试，统计延迟与失败率。
4. 评估键盘钩子方案，决定是否消除触发侧“先翻下一页”的缝隙。
5. 评估单文件分发的可行边界（模式 A 可单文件；模式 B/B2 必须带 HTML/启动器）。
